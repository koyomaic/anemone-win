# 定时计划（relay-plan）

用户想**周期性地**做某事（每天/每周/每月/每隔/定时/到点/提醒我…）。

> **主路径在系统侧**：用户消息若以「定时」或「计划」开头，relay-avatar 会在**进到你之前**
> 就地解析并建好计划，你根本不会收到它。所以本技能只是**兜底**——万一你收到一条没被拦截的
> 周期性请求，按下面处理。

> **铁律：绝不"当场执行"那个周期性任务。** 不要生成报表、不要发消息、不要建日程、不要跑数据。
> 你唯一该做的是：输出一个 ```plan 标记 + 一句简短确认。创建由系统带凭据完成。

## 你能做什么 / 不能做什么
- **能**：理解自然语言 → 在回复里输出一个 ```plan 代码块（JSON）。
- **不能**：自己调 API 建计划（沙箱无凭据）；**不能**去执行那个周期任务。

## 标记格式（严格遵守）
在回复**末尾**输出一个围栏代码块，语言标注为 `plan`，内容是一个 JSON 对象：

````
```plan
{"op":"create","name":"经营日报","on_calendar":"*-*-* 08:00:00","description":"生成昨日经营日报并发送给王洪彬","priority":"normal","read_only":false}
```
````

- 一个回复可含**多个** ```plan 块（如用户一次要建好几个）。
- 块外照常写给人看的短句（如「好的，已安排每天 8 点跑经营日报」）。系统会把标记从正文里剔除并追加权威确认。

## op 取值
| 用户意图 | op | 必填字段 |
|---|---|---|
| 建一个周期任务 | `create` | `on_calendar`, `description`（`name` 可选，缺省由 description 生成） |
| 看有哪些计划 | `list` | 无 |
| 删掉某计划 | `delete` | `name`（可给关键词，系统按名匹配） |
| 停用 / 启用 | `disable` / `enable` | `name` |

`create` 可选字段：`priority`（`normal`/`urgent`）、`read_only`（true/false）。
`description` 是**到点真正执行的任务指令**，写成一句可独立执行的话（含"发给谁/做什么"）。

## on_calendar（systemd OnCalendar，系统会用 systemd-analyze 校验）
| 需求 | 表达式 |
|---|---|
| 每天 08:00 | `*-*-* 08:00:00` |
| 每周一 09:30 | `Mon *-*-* 09:30:00` |
| 工作日 09:00 | `Mon..Fri *-*-* 09:00:00` |
| 每天 09:00 和 18:00 | `*-*-* {09,18}:00:00` |
| 每月 1 号 09:00 | `*-*-01 09:00:00` |
| 每 30 分钟 | `*:0/30:00` |
| 每 2 小时 | `*-*-* 0/2:00:00` |
| 每小时整点 | `*-*-* *:00:00` |

- 时间用 24 小时制。"下午3点"→`15:00`，"晚上10点"→`22:00`，"中午"→`12`，"早上/上午"原样。
- 星期：`Mon Tue Wed Thu Fri Sat Sun`。

## 何时该追问而不是猜
- 用户没说清**时间/频率**（如"定期跑一下"）→ 先问"多久一次、几点？"，不要瞎填。
- 用户没说清**做什么**（description 无法独立执行）→ 追问。
- 频率高于一分钟一次 → 拒绝并说明（系统也会拦）。

## 既跑又排
用户说"现在先跑一次，以后每天8点也跑"→ **照常把这一次的任务做完**，**同时**输出 `create` 标记。

## 示例
用户："每个工作日早上九点半提醒我开晨会"
回复：
好的，已安排工作日 9:30 提醒你开晨会。
````
```plan
{"op":"create","name":"晨会提醒","on_calendar":"Mon..Fri *-*-* 09:30:00","description":"提醒王洪彬开晨会","priority":"normal","read_only":false}
```
````

用户："我设过哪些定时计划？"
回复：帮你查一下～
````
```plan
{"op":"list"}
```
